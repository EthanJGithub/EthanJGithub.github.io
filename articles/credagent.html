CredAgent: a multi-agent loan underwriter built to be audited

June 2026·8 min read·CredAgent
Open live demo ↗View code ↗

CredAgent underwrites consumer loans end to end with a team of cooperating agents — and it's designed so that every decision it makes can be reproduced, explained, and defended. In lending, a model that can't explain itself is a liability, not an asset. So CredAgent treats explainability, fairness, and auditability as requirements, not extras.

The pipeline

CredAgent is a LangGraph state machine of five agents, each with one job, passing an explicit shared state forward:

Ingestion -> Risk Scoring -> Policy Compliance -> Decision -> Audit
  • Ingestion validates and structures the application.
  • Risk Scoring runs an XGBoost model and attributes the score with SHAP.
  • Policy Compliance checks the decision against regulation via RAG over policy text.
  • Decision produces an approve/deny/refer outcome and the adverse-action reasons.
  • Audit writes an immutable record of inputs, model version, prompts, and outputs.

I chose LangGraph specifically because the transitions are deterministic and inspectable. For a regulated workflow you want to know exactly which state produced which output — a graph gives you that; a free-form agent loop does not.

The model, and why it's explainable

The risk model is an XGBoost classifier trained on the real 307K-row Home Credit dataset (246K train / 61K validation), reaching a validation ROC-AUC of 0.76. Every individual decision is attributed with SHAP, so the system can say why a particular applicant was scored the way they were — which is exactly what you need to generate a compliant adverse-action notice.

Compliance is the feature

Adverse-action notices from SHAP

Under ECOA / the CFPB, a denied applicant is owed specific reasons. CredAgent generates those directly from the SHAP attributions — the top contributing factors become the notice — so the explanation a regulator sees is the same signal the model actually used.

RAG over CFPB policy

The Policy Compliance agent grounds its checks in real regulatory text using a retrieval step over a ChromaDB index of CFPB material, rather than relying on the LLM's memory. The decision cites policy it actually retrieved.

Fair-lending testing, kept separate from scoring

CredAgent runs disparate-impact testing (the four-fifths rule) and enforces prohibited-basis exclusion — features like sex and education are deliberately kept out of the scoring model. Critically, fairness monitoring is a separate component from the scoring model, so the model is never optimizing against its own fairness check.

Design principle. Keep fairness monitoring outside the scoring model. The moment the model can see its own fairness metric, it learns to game it. Separation keeps the audit honest.

Human-in-the-loop and durable state

Borderline and high-impact decisions are routed to a human-in-the-loop checkpoint rather than auto-decided — escalation is a first-class path, not an afterthought. Decisions, model versions, and the exact prompts are persisted to a SQLite store so the system never depends on in-memory-only state, and PSI-based drift monitoring watches the production input distribution over time.

How it's served

A FastAPI backend exposes the pipeline; there's a Streamlit cloud demo for quick access and a React/Vite + Nivo frontend with an "AI Evidence Hub" that surfaces the audit trail. The whole thing is deployed and demoable.
