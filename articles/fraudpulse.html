FraudPulse: fraud detection, reported with the honest metric

May 2026·7 min read·FraudPulse
Open live demo ↗View code ↗

FraudPulse is a real-time fraud-detection service: a transaction comes in, the model scores it, and the system returns an action — ALLOW, REVIEW, or FLAG. It's built around one conviction: in fraud, the metric you report is a moral choice as much as a technical one, and accuracy is the wrong one.

Why accuracy lies

The real ULB credit-card dataset FraudPulse trains on has a 0.17% fraud rate. A model that predicts "not fraud" for every transaction is 99.83% accurate and completely useless. Under that kind of extreme class imbalance, accuracy and even ROC-AUC look flattering while hiding the only thing that matters: how well you catch the rare positives without drowning analysts in false alarms.

So FraudPulse reports PR-AUC (precision-recall AUC) as its headline number — 0.88 — along with the operating point it actually runs at: 94% precision at 83% recall. That's the honest way to describe a rare-event detector.

The honest metric. Match the metric to the business cost. For a 0.17%-positive problem, PR-AUC and precision-at-threshold tell the truth; accuracy tells a comfortable lie.

Two models, supervised and unsupervised

FraudPulse combines a supervised XGBoost classifier with an unsupervised IsolationForest. The supervised model learns the patterns of known fraud; the IsolationForest flags anomalies that don't look like anything in the training data — the novel attacks the labels haven't caught up to yet. Together they cover both "fraud we've seen" and "this is weird."

A scoring service, not a notebook

The model is wrapped in a FastAPI scoring API that returns the ALLOW / REVIEW / FLAG decision with the score, backed by a SQLite store. A live stream simulator replays transactions so you can watch decisions happen in real time, and a React/Vite + Nivo operations dashboard visualizes the flow — the things a real fraud team would actually look at.

The agentic part: data onboarding that self-corrects

The most interesting piece isn't the model — it's how a new dataset gets in. FraudPulse includes an LLM agent that onboards any labelled CSV: it profiles the file, reasons about which column is the label and what each feature means, and self-corrects against data-quality validation. It's schema-agnostic, driven by a DatasetConfig, so the whole service can be pointed at a different fraud dataset without rewriting the pipeline.

A fraud-rate plausibility gate

One check I'm particularly fond of: a fraud-rate plausibility gate. If an uploaded dataset's positive rate looks implausible — say it's 30% fraud — that's a strong signal the data was resampled or mislabeled, and the agent flags it before a single model is trained. The data lies before the model does; the gate catches it early.
